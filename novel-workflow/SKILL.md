# 小说写作统一入口（novel-workflow）

路径基准：文中所有文件路径均相对于项目根目录。

## 职责

本技能是长篇小说写作流程的统一入口，智能判断用户意图并分派到对应子流程：

- **场景A：新项目初始化** — 在用户当前工作目录生成完整的小说工程骨架（技能 + 规则 + 模板）
- **场景B：继续章节创作** — 调用已有项目的写作流程链（context-collection → plot-options → chapter-drafting → prose-polish → plot-review → index-update）

## 意图判断规则

| 用户输入特征 | 判断为 | 执行流程 |
|---|---|---|
| "新建"、"新项目"、"搭建骨架"、"从零开始"、"/novel init" | A. 新项目初始化 | 执行【初始化流程】 |
| "写小说"、"写第一章"、"继续创作"、"/novel write"、"下一章" | B. 章节创作 | 执行【章节创作流程】 |
| "参考作品分析"、"拆书" | A. 带拆书的新项目初始化 | 执行【初始化流程 + 拆书】 |
| 意图不明 | 询问用户 | 列出两个选项让用户选择 |

## 初始化流程（场景A）

当用户要新建小说项目时，按以下步骤执行：

### 步骤1：确认项目参数

向用户确认以下信息（若未提供）：
- 题材类型（玄幻/仙侠/奇幻 / 都市/现实 / 科幻 / 纯文学）
- 作品体量（短篇 / 中篇 / 长篇 / 超长篇）
- 写作目的（网文连载 / 纯文学发表 / 短剧影视改编 / 个人兴趣）
- 是否有参考作品（有书名则调用 book-analysis-agent 拆书）

### 步骤2：确定工作目录

- 若用户已指定目录：使用该目录
- 若用户未指定：在当前工作目录创建 `新题材/` 子目录

### 步骤3：复制引擎层

从本技能的模板库中复制以下文件到新项目目录：

```
.trae/skills/
├── book-analysis-agent/SKILL.md
├── chapter-drafting/SKILL.md
├── chapter-review-agent/SKILL.md
├── context-collection/SKILL.md
├── index-update/SKILL.md
├── master-writer-agent/SKILL.md
├── novel-writing/SKILL.md
├── plot-options/SKILL.md
├── plot-review/SKILL.md
├── prose-polish/SKILL.md
└── volume-1-agent/SKILL.md

规则/
├── 审查规则.md
├── 文风规则.md
└── 用词习惯.md

索引/
├── 章节摘要.md
├── 故事线.md
├── 人物线.md
└── 伏笔登记.md
```

### 步骤4：创建内容层模板

在新项目目录创建以下模板文件（带示例参数）：

- `大纲.md` — 含玄幻/都市/科幻三种方向的示例段落
- `设定/世界观.md` — 含三种题材的示例结构
- `设定/主要人物卡.md` — 含三种题材的语气档案示例
- `设定/能力体系.md` — 玄幻向（力量等级）/ 都市向（留空说明）/ 科幻向（技术规则）
- `设定/势力与地理.md` — 含三种题材的示例
- `细纲/第1卷_细纲.md` — 含三种题材的示例章节规划
- `参考作品/参考作品笔记.md` — 空模板

### 步骤5：根据题材调整规则文件

根据用户选择的题材类型，调整 `规则/` 下的三个文件：

**玄幻/仙侠/奇幻**：
- 钩子密度：每 800~1000 字
- 对话:描写：4:6
- 内心独白：限 2~3 句/章
- 禁用词：避免现代词汇
- 高频动词：攥、眯、沉声、瞥、凛、寒

**都市/现实**：
- 钩子密度：每 600~800 字
- 对话:描写：5:5（对话驱动）
- 内心独白：限 1~2 句/章
- 禁用词：避免玄幻化表达
- 高频动词：盯、皱、叹、挪、攥

**科幻**：
- 钩子密度：每 500~800 字（影视改编向更密集）
- 对话:描写：3:7 或 4:6（对话驱动）
- 内心独白：限 2~3 句/章
- 禁用词：避免过度文艺化
- 高频动词：调、扫、读、触、切
- 新增：科技术语首次出现需自然解释

**纯文学/文艺**：
- 钩子密度：每 1200~1500 字（宽松）
- 对话:描写：3:7（描写为主）
- 内心独白：放宽至 3~5 句/章
- 禁用词：无特殊限制
- 高频动词：依题材而定

### 步骤6：（可选）拆书分析

若用户提供参考作品书名：
1. 调用 `book-analysis-agent` 分析参考作品
2. 将分析结果写入 `参考作品/参考作品笔记.md`
3. 根据拆书结果微调规则文件参数

### 步骤7：输出初始化报告

向用户输出：
- 项目目录位置
- 已生成的文件清单
- 下一步操作建议（填写大纲 → 落设定 → 建细纲 → 开始写作）

## 章节创作流程（场景B）

当用户要继续章节创作时，按以下步骤执行：

### 步骤1：确认项目上下文

- 检查项目是否存在 `.trae/skills/novel-writing/SKILL.md`
- 若不存在，提示用户先执行初始化流程
- 读取当前状态：最新章节号、最近更新的索引文件

### 步骤2：执行写作流程链

按顺序调用以下技能：

1. **context-collection** — 汇集本章所需上下文
2. **plot-options** — 推演 2~3 个剧情走向，自主选定推荐项
3. **chapter-drafting** — 生成正文（3000~5000 字）
4. **prose-polish** — 文风润色
5. **plot-review** — 剧情审查
6. **index-update** — 更新索引（章节摘要、故事线、人物线、伏笔登记）

### 步骤3：输出交付物

向用户输出：
- 正文内容（Markdown 格式）
- 本章摘要（100~150 字）
- 需更新的故事线/人物线/伏笔条目清单
- 下一章创作建议

---

## 约束

- 禁止跳过初始化流程直接创作（除非项目已存在）
- 禁止在初始化过程中修改用户已有文件
- 禁止未经用户确认就自动写正文
- 初始化完成后，必须等待用户确认再继续
- 若用户意图不明，必须先询问再执行

---

## 冲突处理

若本技能与 `volume-1-agent` 冲突，以 `volume-1-agent` 的本卷补充为准。

若规则文件冲突，优先级为：审查规则 > 用词习惯 > 文风规则 > 智能体默认行为。

若冲突无法判定，暂停并询问用户。
